FR-10 — Visualization Dashboard & Maintenance Advisory
1. Objective

The system shall provide an intuitive visualization dashboard for UAV operators, propulsion engineers, and maintenance personnel to monitor engine condition, review faults, understand Digital Twin outputs, evaluate predictive analytics, and receive maintenance advisories.

The interface shall present complex engine-health information in a clear, actionable, and role-appropriate manner.

2. Scope

FR-10 covers:

Dashboard architecture
User roles
Real-time engine overview
Live parameter visualization
Engine Health Index
Subsystem health
Alerts and notifications
Fault visualization
Digital Twin visualization
AI/ML predictions
RUL visualization
Trend analysis
Mission information
Maintenance advisory
Historical analysis
Mission replay integration
Report access
Data freshness/status
User interaction
Acceptance criteria

│          STATUS: NORMAL            │
│          RPM: 4200                 │
│                                    │
│  CHT: 175°C       EGT: 702°C       │
│  Oil P: 4.1 bar   Oil T: 92°C      │

7. Engine Health Index Visualization

The dashboard shall prominently display the overall Engine Health Index.

Example:

       ENGINE HEALTH

            87 / 100

         ● DEGRADED

The health index shall be accompanied by appropriate context such as:

Current health state
Trend
Confidence
Major contributing subsystem

Example:

Health: 87
Trend: ↓
Confidence: 91%
Main Concern: Mechanical
8. Subsystem Health Visualization

The dashboard shall display subsystem health separately.

THERMAL          91%
LUBRICATION      86%
COMBUSTION       89%
MECHANICAL       78%
ELECTRICAL       95%

The user shall be able to select a subsystem and inspect its relevant parameters and trends.

9. Alerts & Notifications

The dashboard shall display real-time alerts generated by the fault/health modules.

Example:

⚠ WARNING

EGT deviation increasing

Severity: WARNING
Confidence: 84%
Time: 14:32:18

Alerts shall include:

Alert type
Severity
Timestamp
Affected subsystem
Confidence where available
Supporting information
10. Fault Visualization

Detected and predicted faults shall be clearly represented.

Example:

FAULT DETECTED

Possible:
Injector Abnormality

Confidence: 87%
Severity: WARNING

Evidence:

EGT deviation ↑

The dashboard shall allow the user to inspect supporting parameters.

11. Digital Twin Visualization

The dashboard shall provide a visual representation of the Digital Twin state.

This does not necessarily require a complex 3D engine model.

Initial prototype may use:

PHYSICAL ENGINE
      ↕
DIGITAL TWIN
      ↕
EXPECTED STATE
      ↕
ACTUAL STATE
      ↕
DEVIATION

The user should be able to see:

Current twin state
Expected values
Actual values
Residuals
Health condition
Degradation state
12. AI/ML Prediction Visualization

AI/ML results shall be displayed in an understandable format.

Example:

AI ANALYSIS

Anomaly Score:       0.86

Possible Fault:
Combustion Instability

Probability:         82%

Main Factors:
EGT deviation       HIGH
Fuel Flow           HIGH
RPM variation       MEDIUM

The dashboard shall avoid presenting AI predictions without context.

13. RUL Visualization

Where a validated RUL model is available, the dashboard shall display the estimated Remaining Useful Life.

Example:

REMAINING USEFUL LIFE

Estimated: 142 hours

Uncertainty:
±18 hours

Trend:
↓ Degrading

The interface should make clear that RUL is an estimate with uncertainty, not a guaranteed failure time.

16. Maintenance Advisory

The system shall provide maintenance recommendations based on:

Current health
Fault diagnosis
Degradation trend
RUL
Fault severity
Mission history
Confidence

Example:

MAINTENANCE ADVISORY

Possible cooling degradation detected.

Recommendation:
Inspect cooling system during
next maintenance opportunity.

Priority: Medium
Confidence: 89%

The system should distinguish between:

Observation

Inspection recommendation

Maintenance recommendation

rather than automatically commanding a maintenance action.

View historical health

Inspect AI predictions
Compare missions
Review Digital Twin behaviour

Concept:

Dashboard
   │
   ├── LIVE
   ├── HISTORY

   ├── FAULTS
   └── REPORTS
18. Data Status & System Health

The dashboard shall show the status of the data and software system itself.

Example:

SYSTEM STATUS

Telemetry:       ● LIVE
Digital Twin:    ● SYNCED
AI Model:        ● ACTIVE
Database:        ● CONNECTED
Data Quality:    ● GOOD

If something fails:

⚠ AI MODEL UNAVAILABLE

Health monitoring
continues using available
model-based methods.

This prevents users from confusing engine health with system/data health.

19. User Interaction & Report Access

The dashboard shall allow users to:

Filter parameters
Select time ranges
Zoom charts
Select mission
Select subsystem
Inspect fault events
View supporting evidence
Open mission reports
Export relevant data/reports

The interface should provide progressively deeper information:

Overview
   ↓
Subsystem
   ↓
Parameter
   ↓
Event
   ↓
Supporting Data

This keeps the primary interface simple while allowing engineers to perform detailed investigation.

20. Acceptance Criteria

FR-10 shall be considered complete when:

 A functional engine-health dashboard is available.
 User roles are supported.
 Real-time engine parameters are displayed.
 Overall Engine Health Index is displayed.
 Subsystem health is displayed.
 Real-time alerts are displayed.
 Fault information is visualized.
 Digital Twin state is visualized.
 AI/ML predictions are displayed.
 RUL is displayed when available.
 Historical trends can be viewed.
 Mission information is displayed.
 Maintenance advisories are available.
 Mission replay can be accessed.
 Historical reports can be accessed.
 Telemetry/data-system status is visible.
 Users can interact with charts and filters.
 Important predictions show supporting evidence/confidence.
 Dashboard remains usable when individual analytics components are unavailable.
